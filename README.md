# TraySuite

Modular tools for Windows 10 and 11, available in Free and Pro tiers. [Hub and free apps](public/README.md) · [Dimmli documentation](public/Apps/Dimmli/README.md)

- `public/` contains Hub, Suite.Core, and the free modules Dimmli, Awake, ClipPlain, PinWin, and PowerFlip. You can copy this directory into a separate repository and build `public/TraySuite.sln` independently.
- The root `TraySuite.sln` builds the public projects. Sweep, Boost, Pulse, Volly, SnapKit, Unlocker, and NetWatch belong in the private checkout under the ignored `pro/` directory. Each app uses the shared .NET 10 Desktop Runtime for its architecture.

## Build packages

Install the .NET 10 SDK and Python 3.11 or later. Building the Hub installer requires Windows and Inno Setup 6.3 or later.

```powershell
dotnet build TraySuite.sln -c Release
python installer/build.py build --scope public --runtime win-x64
python installer/build.py build --scope public --runtime win-arm64
python installer/build.py build --scope pro --runtime win-x64
python installer/build.py build --scope pro --runtime win-arm64
python installer/build.py merge --scope public --inputs artifacts/public --output artifacts/release
python installer/build.py merge --scope pro --inputs artifacts/pro --output artifacts/private-release
```

Add `--no-setup` when building the public packages on Linux or when you need a portable Hub. ZIP archives, manifest fragments, and the portable Hub appear under `artifacts/public/<runtime>`. The Inno Setup installer checks for the matching Desktop Runtime version and architecture. If the runtime is missing, it downloads the Microsoft installer, verifies its pinned SHA-256 checksum, and asks for permission to run the system installer.

The public workflow builds the installers and Free packages and merges their metadata into `manifest.json`. From a private repository with Pro projects under `Apps/`, call `misiek1205/dimmli/.github/workflows/build-pro.yml@<ref>` and set `public_ref` to the public commit or tag to build against. The workflow generates both sets of Pro ZIPs and `manifest-pro.json` in the private run. The public manifest leaves `download_url` and `sha256` empty for Pro packages. When merging the public manifest, pass `--pro-metadata artifacts/private-release/manifest-pro.json` to publish Pro package versions and sizes. Download URLs and checksums stay in the private manifest.

By default, Hub fetches `manifest.json` and the Free packages from the latest GitHub release of `misiek1205/dimmli`. Upload the public manifest, both installers, and all Free ZIP archives to that release. Publish private release files through the Pro package source.

## Local development

On Windows, close Hub and run `TraySuite.Hub.exe --local C:\packages`. You can also set `TRAYSUITE_LOCAL_PACKAGES`. The directory can contain a generated manifest with ZIP archives, ZIP archives with matching `<App>-<runtime>.zip.sha256` files, or `dotnet publish` output under `<App>\<runtime>`. Hub verifies SHA-256 checksums for packages from a manifest or ZIP archives with checksum files. Local executables can load libraries placed alongside them. The `DEV-PRO-TEST` activation key works in Debug builds, including with a local `manifest-pro.json` and separately published Pro Debug binaries.

## Configure Pro sales and downloads

| Build-time variable | Purpose |
| --- | --- |
| `TRAYSUITE_STORE_ID`, `TRAYSUITE_PRODUCT_ID` | Lemon Squeezy store and product IDs checked during activation |
| `TRAYSUITE_CHECKOUT_URL` | HTTPS URL for purchasing a license key |
| `TRAYSUITE_DOWNLOADS_URL` | HTTPS URL for the service that issues private package download links |
| `TRAYSUITE_PRIVATE_PACKAGE_BASE` | Optional base URL for package links in the manifest generated by the private workflow |

Hub activates license keys through the official Lemon Squeezy endpoint and encrypts the key and instance ID with DPAPI for the current Windows user. [License activation documentation](https://docs.lemonsqueezy.com/api/license-api/activate-license-key)

The official Lemon Squeezy response includes license status and product metadata. Hub accepts a `download_manifest_url` extension in the response or sends JSON containing `license_key` and `instance_id` to the configured download service. The service verifies the instance and product IDs on the server and returns `{"download_manifest_url":"https://…"}`. That URL points to a manifest containing short-lived HTTPS package URLs and their SHA-256 checksums. Checkout configuration and the download service are separate parts of the deployment.

Lemon Squeezy closed new store registrations on November 16, 2026, and will stop processing transactions on March 31, 2027. [Provider migration timeline](https://docs.lemonsqueezy.com/migration)

## Windows integrations

- **Sweep** previews cleanup results. It includes files older than 24 hours and uses a seven-day threshold for Windows Update files. It skips reparse points, protected files, and downloaded updates while the Windows Update service is running.
- **Boost** tries to enable the Ultimate Performance or High Performance power plan and restores the previous plan afterward. The Dimmli integration restores brightness when the mode ends or the Boost process exits. Boost enables Windows Do not disturb through an undocumented shell COM interface and restores the previous profile after the game. If the interface is unavailable, the notification rules button opens Windows Settings. Boost asks selected apps to close and relaunches the ones that closed after the game. [Windows notification rules](https://support.microsoft.com/en-us/windows/experience/focus-stay-on-task-without-distractions-in-windows)
- **Pulse** tries to read temperatures through WMI and NVIDIA NVML. A dash indicates that a reading is unavailable. LibreHardwareMonitor can expose additional CPU and GPU sensors through WMI.
- **Volly** mixes active Core Audio sessions. Change the default output from the popup list or with `Ctrl+Alt+O`. Output switching uses the Windows `IPolicyConfig` interface. [Core Audio interfaces](https://learn.microsoft.com/en-us/windows/win32/coreaudio/core-audio-interfaces)

The public workflow tests Hub installation and uses the Hub popup to install, open, and uninstall free modules. It also checks the Dimmli CLI and removal of the Hub startup entry. Hardware readings, clipboard behavior, the system tray, brightness control, and audio require testing in an interactive Windows session.
